heyctl

The CLI for app-lb's admin API. By default it talks to http://127.0.0.1:9090; reach a remote server over an SSH tunnel (ssh -L 9090:127.0.0.1:9090 host) and save it as a context with heyctl login.

Contexts & identity

heyctl login                  # verify credentials, save as a context
heyctl whoami                 # which server, as whom, allowed to do what
heyctl config get-contexts    # manage saved contexts
heyctl logout

Credentials are the Basic pair or a bearer token (--token, HEYCTL_TOKEN, or heyctl login --token-stdin) — an app-token, or a namespace-scoped Heyo API key against Cloud's /namespaces/{ns}/lb door. Machine output is everywhere: -o json, -o yaml, -o name.

Reading the fleet

heyctl get deployments        # also: vms, certs, secrets, jobs, workflows
heyctl describe web           # spec, pool, backends, traffic
heyctl status                 # whole-LB overview
heyctl top                    # CPU/memory for deployments, VMs or the host
heyctl feed                   # namespaces with events — see below

Deployments

heyctl apply -f web.json      # create or replace from a spec (JSON or YAML)
heyctl create deployment …    # the flag-driven alternative
heyctl edit web               # fetch spec → $EDITOR → put back
heyctl scale web --min 1 --max 4
heyctl restart web            # recycle VMs one eviction at a time
heyctl rollout status web     # watch the pool converge
heyctl delete web

Changing one thing

heyctl set image web web-rootfs-v2     # rebuilds the pool
heyctl set env web RUST_LOG=debug      # KEY=VALUE, or KEY- to remove
heyctl set upstreams legacy 10.0.0.5:3000
heyctl set route web --host web.example.com
heyctl set build web --repo https://github.com/example/web

Images

heyctl build web              # run the spec's build block, roll the pool
heyctl pull web               # pull the spec's artifact instead
heyctl artifact login …       # talk to an artifact store directly
heyctl update legacy          # static deployment: run its update commands

Inside a VM

heyctl exec web -- uname -a   # one command; guest exit code becomes heyctl's
heyctl shell web              # interactive PTY (alias: ssh)
heyctl shell web --vm sb-7f3a9c   # …in that VM, not whichever the pool offers

Both go through app-lb, so they work wherever the admin API does — and they wake a scale-to-zero deployment that has no VM running.

Tokens

heyctl token mint NAME [--admin none|view|admin]
                     [-d ID]... [--all-deployments]
                     [--namespace NS] [--expires-in HOURS] [-q]
heyctl token list
heyctl token describe ID
heyctl token set ID [--name…] [--admin…] [-d…] [--never-expires]
heyctl token revoke ID

The secret prints once, on stdout, with commentary on stderr — so TOKEN=$(heyctl token mint agent -d web -q) captures exactly the credential. The listing's scope column shows a namespace wall as team-a:* or team-a:web. See Namespaces for what --namespace means.

Feeds

heyctl feed                   # which namespaces have events
heyctl feed team-a            # events, newest first (-n limits)
heyctl feed team-a --xml      # the RSS document, verbatim
$ heyctl feed team-a
WHEN         KIND      DEPLOYMENT  WHAT
2m ago       issue     web         web: cold start timed out — a request waited 120s… (×3)
1h ago       deployed  web         web deployed — serving at https://web.example.com

See The event feed for how events get there in the first place.

Libraries

The same API surface ships as libraries, wire-pinned against app-lb's golden fixtures so a field can't silently go missing:

  • Rust — the heyctl crate: an async Client, a blocking wrapper, and client.raw() for verbatim JSON.
  • TypeScript — sdk/typescript: new Heyctl({ server, token }) with typed deployments(), exec(), mintToken(), feeds(), feedEvents()…
heyctl completion bash        # also zsh, fish, elvish, powershell
